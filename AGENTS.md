# AGENTS.md — contract for AI coding agents in this repository

This file is read first by Codex, Claude Code and similar agents. Humans: read `README.md` first.

## Purpose

Produce and maintain a **small, transparent, matrix-based LCA calculator** that runs on a frozen
snapshot of TianGong open data, and that reproduces the SVE vs biopile case study within the
tolerances in `tests/expected_results.json`. Teaching clarity beats features.

## Data contracts

**Snapshot (compact form, produced by `data/build_snapshot.py`).**

```
processes.json : [ { uuid, version, name, name_zh, geo, year, type, classification[], comment,
                     sources[{uuid,name}], ref_flow,
                     exchanges[ { dir:"in"|"out", flow:<flow uuid>, name, amount, comment?, ref?:true } ] } ]
flows.json     : { <flow uuid>: { name, type:"Elementary flow"|"Product flow"|"Waste flow"|..., category, prop, unit } }
lcia_methods.json : [ { uuid, name, unit, methodology[], impact_category[], indicator,
                        factors:[ [<flow uuid>, "in"|"out", value]                 ← generic factor: USE THIS
                                  [<flow uuid>, "in"|"out", value, <location>] ] } ]  ← regionalised row: ignore
```

Amounts are in the flow's reference unit (`flows[uuid].unit`). Electricity is in **MJ**, not kWh.
Several EF methods carry one generic row plus up to 36 country rows per flow; build Q from rows with exactly three elements.

**Case bundle (`web/data/case_bundle.json`)** is the pruned subset the web tool loads: the foreground
stages (with converted amounts, default provider and optional `addons`), the provider choices, every process reachable
from them, the flows they reference (a flow may have `type: null` — a broken reference; treat it as unlinked), the 25
characterisation-factor tables restricted to those flows, `producers` (flow → valid provider uuids in the bundle),
`resolution_log` (only the choices made among several candidates; `n_unique_links` counts the rest), `cutoffs`
(foreground and background) and `warnings` (processes with duplicate exchange rows). It is generated by
`reference/build_case_bundle.py`; never edit it by hand.

**Add-ons.** A stage input may carry `addons: [{type:"emission", flow, dir, per_printed_unit, note, source}]` (a documented
direct emission of the foreground stage, e.g. 2.68 kg CO₂ per litre of diesel burned) or `{type:"input", flow, provider,
per_printed_unit, …}` (an extra product input). Amount = `per_printed_unit × amount_printed`, booked on the stage column.

## Matrix conventions (must match `docs/01_matrix_method.md`)

- One column per process; **row i is "the reference product of column i"**, so **A** is square by construction and a
  consumer links to one specific provider column. One row per (elementary flow, direction) in **B**.
- Foreground stages are synthetic columns (reference amount 1) whose inputs are the converted amounts of TianGong product
  flows; a synthetic system column consumes 1 of each stage. Demand **f** = 1 unit of the system column.
- A[i, i] = + reference amount of column i; A[i, j] = − amount of product i consumed by column j. Raw amounts, no normalisation.
  Solve A s = f with a dense solver (a few hundred to ~1,000 columns).
- Inventory g = B s. Impacts h = Q g, where Q[k, i] is the factor of method k for elementary flow i (direction-aware).
- Contribution analysis: per-process h_kj = Σ_i Q[k,i] B[i,j] s_j; **per-stage = impacts of the demand vector restricted to
  that stage column** (exact, by linearity: Σ_stage = total); per-flow = Q[k,i] g_i.
- **Provider resolution:** a product-flow input is linked to the provider named in `case/provider_choices.json` (or
  `_background_overrides`) if present; otherwise to the unique process whose `ref_flow` equals the flow; if several qualify,
  prefer the most specific geography match (count of shared trailing tokens of the location code, e.g. `ZZ-SD-CN` vs
  `SD-CN` = 2, vs `CN` = 1), on ties the more general dataset (shorter location code, so a `CN` consumer gets the national
  mix, not a province), then the most recent `year`, then the smallest uuid, and **record the choice**.
  A process is a valid provider only if its reference exchange is an **output** and it does not consume at least as much of
  its own reference flow as it produces (788 TianGong records are input-referenced emission-coefficient sets; a few "black box"
  records consume their own product — both are excluded from the producers index).
  Product inputs with no provider at all are **cut-offs**: do not fail, list them with their amounts.
- Waste-flow and non-reference product outputs are ignored for A and reported as "unlinked outputs".
- **Duplicate rows:** exact duplicate exchange rows (same flow, direction, amount) are collapsed to one — TianGong has
  re-import duplicates, including doubled reference outputs; rows with the same flow but different amounts (NESPS2
  end-of-pipe technology variants) are summed and the process is listed in `warnings`.
- A product input whose flow is the consumer's own reference flow (CEEIO input-output sectors consume ~5 % of their own
  output) is **netted on the diagonal** (A[u,u] −= amount, logged as rule `self-netted`); it is never resolved to another
  provider and never a cut-off.
- Elementary rows with no factor in any method are "linked but uncharacterised"; report them (e.g. `particles (PM2.5 - PM10)`).

## Known data facts (details in `docs/05_provider_mapping_decisions.md`)

- Most NESPS2 (pollution-census) records in TianGong have **no inputs**: emission coefficients only. Activated carbon, gravel,
  sand, bentonite, tap water and potassium sulphate therefore carry no upstream energy; GAC scores ≈ 0 for climate change
  although the paper attributes 36 % of SVE's impact to it. This is the central teaching point, not a bug to hide.
- No usable diesel or road-freight unit process exists; diesel is a cut-off with a sourced combustion add-on, road freight
  is a monetary CEEIO sector proxy (0.0809 EUR per tkm).
- TianGong has no Korean grid; the China 2019 mix (0.58 kg CO₂/kWh implied) is the default, provinces are alternatives.

## Acceptance

- `python3 reference/run_case.py` and `node web/test.mjs` both pass against `tests/expected_results.json`.
- The web tool opens from `file://` and from GitHub Pages with no build step and no network access except an optional Chart.js CDN.
- Every number shown in the UI can be traced to a process uuid and a flow uuid.

## Rules

- Do not hand-edit anything under `data/snapshot/` or `web/data/`. Regenerate.
- Do not commit the paper PDF or anything under `local/`.
- No secrets, no logins: the public ILCD node is the only remote source.
- Keep dependencies minimal: Python standard library + numpy for the reference; vanilla JS + optional Chart.js for the web tool.
- When you change a convention, update `docs/01_matrix_method.md` and this file in the same change.
