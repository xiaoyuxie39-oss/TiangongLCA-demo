# tests/

`expected_results.json` is produced by `uv run python reference/run_case.py --write-expected` and is the contract between
the reference implementation and anything generated by an agent.

```json
{
  "generated_by": "reference/run_case.py", "snapshot": "<meta.json crawled_at>", "bundle_sha256": "<sha of web/data/case_bundle.json>",
  "tolerance_rel": 0.01,
  "systems": {
    "SVE": {
      "totals":   {"<method name>": {"value": <float>, "unit": "<unit>"}, "... 25 methods"},
      "by_stage": {"<method name>": {"transport": <float>, "foundation": <float>, "...": <float>}},
      "cutoffs":  [ {"item": "diesel_machinery", "amount": 21, "unit": "L", "...": "..."} ],
      "n_processes_solved": <int>
    },
    "Biopile": { "...": "same shape; stages transport, excavation, preparation, operation, gac, backfill" }
  },
  "identities": ["sum_process_equals_total", "sum_stage_equals_total"]
}
```

A test passes when every total and every by-stage value is within `tolerance_rel` of the expected value (absolute
tolerance 1e-9 for values whose expected value is 0), both identities hold to 1e-9 relative, and `n_processes_solved`
matches exactly (it changes only if provider resolution changed). If the bundle's sha256 differs from `bundle_sha256`,
regenerate the expected file first and say so.
